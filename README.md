# 코드위키

SAP / ABAP 수업 필기를 정리한 정적 위키입니다. HTML·CSS·JavaScript로 구성하며 로그인과 게시판은 기존 Supabase 프로젝트를 사용합니다.

## 다른 노트북에서 시작하기

Git과 Node.js LTS를 설치한 후 실행합니다. 별도 npm 패키지 설치는 필요하지 않습니다.

```sh
git clone --branch main https://github.com/ehmaker0219/Codewiki.git
cd Codewiki
node scripts/preview.cjs
```

브라우저에서 http://localhost:4175/ 를 열고 기존 사이트 계정으로 로그인하세요. 서버 종료는 Ctrl+C입니다. 이미 4175 포트를 쓰고 있다면 환경 변수 PORT로 다른 포트를 지정할 수 있습니다.

기존 DB에 연결하므로 노트북을 옮긴다는 이유로 SQL을 다시 실행할 필요는 없습니다. 게시판 작성·관리 작업은 실제 DB에 반영됩니다. DB 비밀번호는 로컬 사이트 실행에 필요하지 않습니다.

## 작업을 옮기는 순서

작업 시작 전 `git pull --ff-only`를 실행합니다. 작업 종료 후 변경 파일을 확인하고 커밋·푸시한 다음 다른 노트북에서 pull하세요. 두 노트북에서 동시에 같은 파일을 수정하면 충돌 조정이 필요할 수 있습니다.

## 파일 구성

- `index.html`: 화면 구조와 스크립트 로딩 순서
- `css/style.css`, `css/theme.css`: 기본 스타일과 블루 위키 테마
- `js/data.js`: 기본 문서·단축키·T-Code와 목차
- `js/class-notes.js`: 11/11~17 필기 기반 문서와 최종 목차 구성
- `js/ui5-data.js`: UI5 자료 (화면 접근은 준비 중으로 비활성화)
- `js/app.js`: 문서 렌더링·검색·링크·역링크
- `js/lesson-days.js`: 원본 필기 5개에 근거한 수업일별 문서
- `js/example-notes.js`: 예제 실행 위치·입력·예상 결과와 SAP 실행 확인 상태
- `js/learning-tools.js`: 본문·코드 검색 및 연결 문서 분류
- `js/practice.js`, `js/practice-ui.js`: 6개 주제 × 10문제, 회차별 중복 없는 출제와 문제 복사
- `js/progress.js`: 계정별 학습 완료 저장·동기화
- `js/auth.js`: 로그인·가입·세션 상태와 기능별 세션 전달
- `js/admin.js`: 관리자 승인 목록·반별 필터·상태 변경
- `js/study.js`, `js/study-store.js`, `editor/study-editor.js`: 관리자 개인 공부방·필기 저장·직접 서식 편집기
- `js/board.js`: 게시판과 작성·답변 처리
- `js/profile.js`, `js/birthdays.js`: 내 프로필과 같은 반의 공개 생일
- `supabase-setup.sql`, `SECURITY-UPDATE.md`: DB 구성·보안 업데이트 안내

원본 PPT·PDF·필기는 이 저장소에 포함하지 않았습니다. 위키에 정리한 내용은 포함되어 있습니다. 비밀번호 메모와 `.env` 파일은 커밋하지 마세요.

## 검증

```sh
# JS/CSS를 수정한 뒤 정적 파일 캐시 키 갱신
node scripts/update-assets.cjs
# 전체 JS 문법, 모든 CJS 회귀 테스트, 캐시 키 일치 검사
node scripts/check.cjs
```

ABAP 예제는 SAP 시스템에서 별도로 실행·검증해야 합니다. SQL 회귀 테스트는 운영 DB가 아닌 별도 테스트 DB에서만 실행하세요.

## 소스와 배포

`main`은 작업 소스이자 GitHub Pages 배포 브랜치입니다. main에 푸시하면 Pages 빌드 후 공개 사이트에 자동 반영됩니다. 새 디자인은 `codex/design-v2`에서 개발하며 main에 통합하기 전에는 공개 사이트가 변경되지 않습니다. 1일차 소스와 배포는 `day1-savepoint`, `day1-deploy` 태그에 보존되어 있습니다.

## 학습 기록 동기화

새 DB를 만들 때는 `supabase-setup.sql` 다음에 `migrations/20261118-learning-progress.sql`을 적용합니다. 기존 프로젝트에는 이 추가 마이그레이션만 적용하면 됩니다. 2026-11-18 기존 Supabase 프로젝트에 적용하고 `tests/learning-progress.sql`의 롤백 검사를 통과했습니다. 테이블 직접 접근은 막고 만료되지 않은 승인 계정의 세션 토큰을 검증하는 RPC로 자신의 기록만 읽고 씁니다.

완료/취소 기록은 계정별로 동기화합니다. 네트워크 실패 시 해당 계정의 브라우저 캐시에 변경을 보관하고 재접속·탭 복귀·재시도 버튼에서 재전송합니다. 같은 문서를 여러 기기에서 바꾸면 서버에 마지막으로 저장된 값이 적용됩니다. 기존 공용 `codewiki_read_docs_v2` 기록은 소유 계정을 알 수 없어 자동 이전하지 않으며 원본 저장값은 남겨 둡니다.

연습문제 회차는 현재 탭을 새로고침하면 초기화됩니다. 고정 문제 번호는 유지됩니다. 예제의 예상 결과는 설명용이며 SAP에서 실행 확인한 결과로 표시하지 않습니다.

## 교육 일정

홈 아래 교육 일정에서 2026-10-19~2027-07-14 월별 달력과 목록을 볼 수 있습니다. `js/schedule-data.js`는 제공된 학생용 엑셀의 전체 일정·주간 달력에서 가져온 193개 날짜, 8개 주요 일정, 5개 교육 단계입니다. 공휴일과 BREAK 날짜 및 평가 명칭은 원본 그대로 유지합니다. `js/schedule.js`가 월 이동·분류 필터·날짜 상세·수업 필기 연결을 담당합니다. 원본의 일자별 일정 안내 문구와 달리 실제 파일에는 전체 일정과 주간 달력 두 시트만 있습니다.

일정 갱신은 openpyxl이 설치된 Python으로 `python scripts/import-schedule.py "원본.xlsx"`를 실행한 뒤 `node tests/schedule.cjs`로 확인합니다. import는 원본 파일을 수정하지 않습니다. 원본 형식이나 교육기간이 바뀌면 importer의 범위와 검증도 함께 수정하세요. 변경 후 `node scripts/update-assets.cjs`로 정적 파일 버전을 갱신하세요.

## 반 생일

회원가입에서 입력한 생일은 기본 표시로 저장합니다. 생년월일을 입력하지 않으면 생일 정보는 저장하지 않습니다. **프로필 설정**에서 추가·수정·삭제하거나 **반 친구들에게 생일 표시**를 변경할 수 있으며, 기존 회원의 공개 설정은 유지합니다. 공개한 승인 회원의 이름과 월·일만 같은 반 교육 일정에 표시됩니다. 달력·목록의 **우리 반 생일** 필터를 지원하며 2월 29일 생일은 윤년에만 해당 날짜에 표시합니다.

새 DB에는 기본 설정 후 `migrations/20261118-birthdays.sql`을 적용합니다. 2026-11-18 기존 Supabase에 적용했습니다. 생년월일은 직접 접근이 차단된 `cw_birthdays` 테이블에 저장하고, 본인 설정 RPC와 관리자 전용 RPC에서만 전체 날짜를 반환합니다. 일반 생일 목록 RPC에는 연도·나이·전체 날짜가 포함되지 않습니다. 관리자 **학생 승인 관리**에서 전체 생년월일을 조회합니다. 테스트용 DB에서 `tests/birthdays.sql`로 권한·동의·반 구분·세션 만료·가입 원자성을 검증할 수 있으며 테스트 데이터는 롤백됩니다.

## 프로필 설정

사이드바 하단에는 이름과 별도의 프로필 설정 버튼만 표시합니다. 설정에서 아이디·소속 반·권한을 확인하고 이름·MBTI·생년월일·생일 공개 여부를 한 번에 저장하며 로그아웃할 수 있습니다. 소속 반과 권한은 이 화면에서 변경하지 않습니다. `migrations/20261118-birthdays.sql` 다음에 `migrations/20261118-profile.sql`을 적용하세요. 2026-11-18 기존 DB에 적용하고 `tests/profile.sql`의 계정 분리·입력 검증·전체 저장/롤백 검사를 통과했습니다.

## 개인 공부방

관리자 로그인 후 **내 공부방** 또는 `#study`에서 개인 필기를 작성합니다. 글을 선택하고 굵게·형광펜·기울임·제목·목록·인용·코드를 누르면 본문에 바로 적용됩니다. 선택 없이 굵게·형광펜을 켜고 이어서 작성할 수도 있습니다. Ctrl+B는 굵게, Ctrl+I는 기울임, Ctrl+Z는 실행 취소, Ctrl+Shift+Z는 다시 실행, Ctrl+S는 저장입니다. 노트를 바꾸면 실행 취소 기록도 분리됩니다. 기존 Markdown 노트는 서식이 적용된 모습으로 열리며 UTF-8 TXT/MD 가져오기와 MD 내려받기를 지원합니다. 제목은 120자, 저장되는 Markdown 본문은 20만 자까지 지원합니다.

Tiptap/ProseMirror 편집기는 관리자 공부방에 진입할 때만 로드됩니다. `editor/study-editor.js`를 수정할 때는 `pnpm install --frozen-lockfile` 후 `pnpm build:editor`를 실행하고 `node scripts/update-assets.cjs`로 캐시 키를 갱신합니다. 생성된 `js/study-editor.js`와 의존성 라이선스 고지 파일도 함께 관리하므로 다른 컴퓨터의 미리보기와 GitHub Pages는 별도 빌드 없이 동작합니다. 본문 저장 형식과 DB 스키마는 그대로 유지합니다.

입력이 멈추면 1.2초 후 서버에 자동 저장합니다. **저장됨** 표시를 확인하면 다른 기기에서도 같은 관리자 계정으로 목록을 열 수 있습니다. 전송되지 않은 현재 필기는 계정별 브라우저 임시 저장소에 보관하고 다시 로그인/접속할 때 복원합니다. 브라우저 저장이 차단되거나 가득 찼다면 안내가 나오므로 서버 저장 또는 내려받기를 사용하세요. 다른 창/기기에서 바뀐 노트는 자동 덮어쓰지 않습니다. 현재 글을 내려받아 보관하고 **서버 글 불러오기**로 최신본을 확인한 뒤 내용을 합칠 수 있습니다. 삭제는 확인 후 영구 삭제됩니다.

`migrations/20261118-study-notes.sql`은 기본 DB 구성 이후 적용합니다. 2026-11-18 기존 Supabase에 적용하고 `tests/study-notes.sql`의 롤백 검사를 통과했습니다. `cw_study_notes`는 RLS를 켜고 직접 테이블 접근을 차단하며 RPC가 관리자 역할·세션 만료·소유 계정·수정 버전을 검사합니다. 일반 회원에게 메뉴가 보이지 않는 것에 더해 서버에서도 접근이 거부됩니다. HTML·외부 이미지 삽입을 지원하지 않습니다. Markdown을 제한된 문서 구조로 변환하며 HTML은 실행되지 않는 글자로 취급합니다. 노트 본문은 GitHub에 저장하지 않습니다.

## 코드 구조와 유지보수

문서 데이터는 index.html의 스크립트 순서대로 조합한 뒤 app.js가 읽습니다. 실행 중 문서를 변경하는 구조는 아니므로 검색용 소문자 텍스트와 역링크 색인은 한 번 만들고 재사용합니다. 문서 데이터를 동적으로 바꾸는 기능을 추가한다면 색인 무효화도 함께 구현해야 합니다.

인증은 auth.js가 담당하고 프로필·학습 기록·생일·관리자 화면에 세션을 전달합니다. admin.js는 승인 목록을 표시하는 역할만 맡으며, 반 필터는 이미 읽은 목록에 적용합니다. 게시판은 같은 세션에서 동시에 시작한 조회만 공유하고, 쓰기 성공 후에는 새로 조회합니다. 화면 이동·팝업 닫기·세션 변경 이후 도착한 응답은 해당 화면을 갱신하지 않습니다.

문서 링크 이벤트는 한 번 등록한 위임 방식으로 처리합니다. 학습 기록 동기화는 목차 전체를 다시 만들지 않고 완료 표시만 갱신합니다. UI를 추가할 때 같은 화면의 재렌더링마다 전역 이벤트나 네트워크 조회를 반복해서 등록하지 않도록 주의하세요.

검증 명령은 외부 패키지 설치 없이 Node.js로 실행하며 운영 DB를 호출하지 않습니다. 개별 테스트는 `node tests/파일명.cjs`로 실행할 수 있습니다. `tests/async-views.cjs`는 지연 응답·중복 조회·저장 실패를, `tests/render-efficiency.cjs`는 불필요한 DOM 변경과 동적 링크 처리를 검증합니다.

사이트 하단의 최근 업데이트는 `node scripts/update-assets.cjs` 실행 시 HTML·JS·CSS 변경이 있을 때 갱신되는 사이트 파일 생성 시각입니다. 한국 시간(KST)으로 표시하며, 새로고침이나 같은 파일의 재검사로 바뀌지 않습니다. 게시글·프로필 등 DB 데이터의 수정 시각과는 별개입니다.
