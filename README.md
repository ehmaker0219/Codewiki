# 코드위키

SAP / ABAP 수업 필기를 정리한 정적 위키입니다. HTML·CSS·JavaScript로 구성하며 로그인과 게시판은 기존 Supabase 프로젝트를 사용합니다.

## 다른 노트북에서 시작하기

Git과 Node.js LTS를 설치한 후 실행합니다. 별도 npm 패키지 설치는 필요하지 않습니다.

```sh
git clone --branch main https://github.com/ehmaker0219/Codewiki.git
cd Codewiki
node scripts/preview.cjs
```

브라우저에서 http://localhost:4175/ 를 열고 기존 사이트 계정으로 로그인하세요. 서버 종료는 Ctrl+C입니다. 이미 4175 포트를 쓰고 있다면 환경 변수 PORT로 다른 포트를 지정할 수 있습니다.

기존 DB에 연결하므로 노트북을 옮긴다는 이유로 SQL을 다시 실행할 필요는 없습니다. 게시판 작성·관리 작업은 실제 DB에 반영됩니다. DB 비밀번호는 로컬 사이트 실행에 필요하지 않습니다.

## 로그인·가입 보안 보완

`migrations/20261119-auth-hardening.sql`은 기본 설정·생일·출석부 가입 마이그레이션을 적용한 뒤 적용합니다. 기존 로그인/가입 구현은 외부 호출 권한이 없는 `cw_auth_private` 스키마로 옮기고, 공개 API는 공통 검사를 통과한 후 호출합니다. 과거 가입 API와 남은 오버로드도 우회 경로가 되지 않도록 권한을 제한합니다. 인증 보완 이후 기본 설정 SQL은 재실행을 차단합니다. 구 마이그레이션을 재실행했다면 **반드시 최신 최종 마이그레이션(`migrations/20261124-review-hardening.sql`)을 마지막에 적용**합니다. 전체 순서는 [보안 업데이트 안내](SECURITY-UPDATE.md)를 따릅니다.

로그인·가입·관리자 비밀번호 재설정은 브라우저에서 JWE(RSA-OAEP-256 + A256GCM)로 암호화해 `secure-auth` Edge Function에 전송합니다. 개인키는 서버 비밀 설정에만 보관하고, 60초 만료·중복 요청 차단·기존 권한 검사를 적용합니다. 기존 평문 인증 RPC는 일반 클라이언트가 호출할 수 없습니다. 이 버전은 프런트엔드와 서버 함수·DB 마이그레이션을 함께 적용해야 하며, 암호화 실패 시 평문으로 우회하지 않습니다. `node scripts/build-auth.cjs`로 브라우저 번들을 재생성합니다. 데모 로그인과 평문 비밀번호 로컬 저장은 제거했습니다.

- 로그인: 계정당 5분에 10회, 클라이언트(서버 HMAC-SHA-256 해시 IP / IPv6 `/64`)당 5분에 120회, 전체 5분에 3,000회. 존재하지 않는 아이디도 같은 횟수 제한·고정 cost-10 bcrypt 연산을 거쳐 아이디 존재 여부 추측을 차단합니다.
- 가입: 같은 아이디당 15분에 3회, 클라이언트당 1시간에 60회, 전체 1시간에 600회. IP 헤더 누락 시 폴백 버킷(`client:missing:*`)으로 제한합니다.
- 비밀번호 재설정(관리자): 관리자당 5분에 10회, 클라이언트당 5분에 60회. 게이트웨이 전체 상한은 5분에 6,000회입니다.
- 신규 비밀번호: 8자 이상, UTF-8 72바이트 이하, bcrypt cost 10(기존 cost-6 해시는 로그인 시 자동 상향). 일부 흔한 비밀번호와 한 글자 반복은 차단합니다. 비밀번호를 자르거나 공백을 제거하지 않습니다. 학생 24시간/관리자 12시간 세션은 유지합니다.
- 실패 시 SQL 예외로 전체 트랜잭션을 취소하지 않고 오류 JSON과 안전 오류 코드(`CW_*`)를 반환하므로 횟수가 남습니다. 가입 본문은 별도 예외 블록에서 실행해 생일 저장 실패 시 계정도 함께 취소합니다.
- 로그인된 회원의 조회·메모 저장은 인증 요청 상한에 포함되지 않습니다. `cw_auth_private.login_logs`는 최근 180일 기록을 유지하며 반려 계정은 제외합니다.

`cw_auth_private`를 API 노출 스키마에 추가하지 않으며 PostgREST는 기본 COMMIT 방식과 클라이언트의 `Prefer: tx=rollback`을 허용하지 않는 설정을 유지합니다. 2026-11-19 기존 Supabase에 인증 보완 SQL을 적용하고 공개 함수·비공개 스키마 접근 권한을 확인했습니다. 운영 테스트 계정은 만들지 않았으며 기존 회원 데이터는 변경하지 않았습니다.

격리된 메모리 PostgreSQL 테스트는 `pnpm install --frozen-lockfile` 후 `node scripts/check.cjs`에 자동 포함됩니다. DB 검사만 실행하려면 `node scripts/test-auth-db.cjs`를 사용합니다. DB URL이나 운영 자격증명을 받지 않습니다. 약한 비밀번호의 기존 재현, 모든 가입 경로, 실패 횟수 유지, 제한 만료, 예전 API 차단, 권한·세션·출석부·생일 원자성, 마이그레이션 재실행 및 메모 소유권·수정 충돌을 검사합니다. 이 마이그레이션 이후 실패 응답은 SQL 예외가 아닌 오류 JSON이므로 이전 `class-roster.sql`/`birthdays.sql`의 실패 검사는 해당 이전 단계에서 실행하며, 이후 검사는 `auth-hardening.sql`을 사용합니다. 이미 설치한 PGlite를 사용할 때만 `CODEWIKI_PGLITE_PATH`로 패키지 경로를 지정할 수 있습니다.

## 소스와 배포

`main`은 작업 소스이자 GitHub Pages 배포 브랜치입니다. main에 푸시하면 Pages 빌드 후 공개 사이트에 자동 반영됩니다. 새 디자인은 `codex/design-v2`에서 개발하며 main에 통합하기 전에는 공개 사이트가 변경되지 않습니다. 1일차 소스와 배포는 `day1-savepoint`, `day1-deploy` 태그에 보존되어 있습니다.

## 학습 기록 동기화

새 DB를 만들 때는 `supabase-setup.sql` 다음에 `migrations/20261118-learning-progress.sql`을 적용합니다. 기존 프로젝트에는 이 추가 마이그레이션만 적용하면 됩니다. 2026-11-18 기존 Supabase 프로젝트에 적용하고 `tests/learning-progress.sql`의 롤백 검사를 통과했습니다. 테이블 직접 접근은 막고 만료되지 않은 승인 계정의 세션 토큰을 검증하는 RPC로 자신의 기록만 읽고 씁니다.

완료/취소 기록은 계정별로 동기화합니다. 네트워크 실패 시 해당 계정의 브라우저 캐시에 변경을 보관하고 재접속·탭 복귀·재시도 버튼에서 재전송합니다. 같은 문서를 여러 기기에서 바꾸면 서버에 마지막으로 저장된 값이 적용됩니다. 기존 공용 `codewiki_read_docs_v2` 기록은 소유 계정을 알 수 없어 자동 이전하지 않으며 원본 저장값은 남겨 둡니다.

연습문제 회차는 현재 탭을 새로고침하면 초기화됩니다. 고정 문제 번호는 유지됩니다. 예제의 예상 결과는 설명용이며 SAP에서 실행 확인한 결과로 표시하지 않습니다.

## 교육 일정

홈 아래 교육 일정에서 2026-10-19~2027-07-14 월별 달력과 목록을 볼 수 있습니다. `js/schedule-data.js`는 제공된 학생용 엑셀의 전체 일정·주간 달력에서 가져온 193개 날짜, 8개 주요 일정, 5개 교육 단계입니다. 공휴일과 BREAK 날짜 및 평가 명칭은 원본 그대로 유지합니다. `js/schedule.js`가 월 이동·분류 필터·날짜 상세·수업 필기 연결을 담당합니다. 원본의 일자별 일정 안내 문구와 달리 실제 파일에는 전체 일정과 주간 달력 두 시트만 있습니다.

일정 갱신은 openpyxl이 설치된 Python으로 `python scripts/import-schedule.py "원본.xlsx"`를 실행한 뒤 `node tests/schedule.cjs`로 확인합니다. import는 원본 파일을 수정하지 않습니다. 원본 형식이나 교육기간이 바뀌면 importer의 범위와 검증도 함께 수정하세요. 변경 후 `node scripts/update-assets.cjs`로 정적 파일 버전을 갱신하세요.

## 반 생일

회원가입에서 입력한 생일은 기본 표시로 저장합니다. 생년월일을 입력하지 않으면 생일 정보는 저장하지 않습니다. **프로필 설정**에서 추가·수정·삭제하거나 **반 친구들에게 생일 표시**를 변경할 수 있으며, 기존 회원의 공개 설정은 유지합니다. 공개한 승인 회원의 이름과 월·일만 같은 반 교육 일정에 표시됩니다. 달력·목록의 **우리 반 생일** 필터를 지원하며 2월 29일 생일은 윤년에만 해당 날짜에 표시합니다.

새 DB에는 기본 설정 후 `migrations/20261118-birthdays.sql`을 적용합니다. 2026-11-18 기존 Supabase에 적용했습니다. 생년월일은 직접 접근이 차단된 `cw_birthdays` 테이블에 저장하고, 본인 설정 RPC와 관리자 전용 RPC에서만 전체 날짜를 반환합니다. 일반 생일 목록 RPC에는 연도·나이·전체 날짜가 포함되지 않습니다. 관리자 **학생 승인 관리**에서 전체 생년월일을 조회합니다. 테스트용 DB에서 `tests/birthdays.sql`로 권한·동의·반 구분·세션 만료·가입 원자성을 검증할 수 있으며 테스트 데이터는 롤백됩니다.

## 6반 가입 명단 확인

6반 신규 가입은 이름 옆 출석번호(1–30)를 입력하고 서버의 비공개 출석부와 일치해야 신청할 수 있습니다. 다른 반은 출석번호 없이 기존대로 신청하며, 모든 반의 관리자 승인 절차는 유지됩니다. 기존 계정에는 재검사를 요구하지 않습니다. 이름·번호 확인은 본인 인증을 대체하지 않습니다.

이 가입 화면을 배포하기 **전에** `migrations/20261118-birthdays.sql`이 적용된 DB에 `migrations/20261119-class-roster-signup.sql`과 별도 보관한 비공개 출석부 seed SQL을 순서대로 적용해야 합니다. 실제 명단 파일은 공개 저장소·사이트 폴더에 두지 않습니다. 명단이 비어 있으면 6반 가입은 차단됩니다. 구버전 가입 RPC도 6반 출석번호 검사 없이 가입할 수 없습니다. `tests/class-roster.sql`은 별도 테스트 DB에서만 실행하며, 가상 명단과 계정은 롤백됩니다.

2026-11-19 기존 Supabase에 검증 함수와 비공개 명단 30명을 한 트랜잭션으로 적용했습니다. 명단 접근 권한·RLS·가입 트리거와 공개 API의 함수 인식을 확인했으며 운영 테스트 계정은 생성하지 않았습니다. 가입 화면은 6반을 선택할 때 출석번호를 입력받습니다.

## 프로필 설정

학생 승인 관리의 **반려됨** 항목에서 가입 요청을 삭제할 수 있습니다. 확인 후 거절된 학생 계정과 연결된 생일·학습 기록을 삭제하며, 기존 게시글은 유지됩니다. 삭제된 아이디로 다시 가입 신청할 수 있습니다. 승인 완료·대기 중인 회원과 관리자 계정은 이 기능으로 삭제할 수 없습니다. 2026-11-19 기존 Supabase에 `migrations/20261119-delete-rejected-signups.sql`을 적용하고 API 연결·권한 거절을 확인했습니다. 운영 계정은 검증 목적으로 삭제하지 않았습니다. 실패 메시지는 해당 요청 아래에 표시됩니다. `tests/admin-delete.sql`은 별도 테스트 DB 전용입니다.

사이드바 하단에는 이름과 별도의 프로필 설정 버튼만 표시합니다. 설정에서 아이디·소속 반·권한을 확인하고 이름·MBTI·생년월일·생일 공개 여부를 한 번에 저장하며 로그아웃할 수 있습니다. 소속 반과 권한은 이 화면에서 변경하지 않습니다. `migrations/20261118-birthdays.sql` 다음에 `migrations/20261118-profile.sql`을 적용하세요. 2026-11-18 기존 DB에 적용하고 `tests/profile.sql`의 계정 분리·입력 검증·전체 저장/롤백 검사를 통과했습니다.

## 관리자 학생 정보

프로필 설정에서도 본인의 출석번호를 확인할 수 있습니다. 번호가 없으면 **미등록**으로 표시하며 수정 입력은 제공하지 않습니다. `migrations/20261119-profile-student-number.sql`은 본인 프로필 조회에 번호만 추가하고 프로필 수정 API는 그대로 유지합니다.

관리자 로그인과 홈·로고 클릭은 학생 정보 화면으로 연결됩니다. 상단의 **현재 접속**은 최근 2분 내 접속 신호가 있는 로그인 회원(관리자 포함)을 계정당 한 명으로 집계하고 이름을 보여 줍니다. 화면이 보이는 탭에서 1분마다 신호를 보내며, 서버는 같은 계정의 55초 이내 중복 쓰기를 생략합니다. 접속 목록은 관리자 화면을 볼 때만 조회합니다. 로그아웃·세션 교체/만료·승인 취소는 집계에서 제외하며, 탭을 닫거나 숨기면 최대 약 2분 후 제외됩니다. 접속 기록은 계정별 마지막 시각 한 건만 보관하고 방문 이력을 쌓지 않습니다. `migrations/20261119-presence.sql`을 적용해야 합니다.

관리자는 **학생 정보** (`#admin/students`)에서 이름·반·출석번호·아이디·생년월일·MBTI·가입 상태·가입일을 조회합니다. 이름/아이디 검색과 반/상태 필터는 조회한 목록에서 처리하며, 새로고침할 때만 다시 요청합니다. 화면을 벗어나거나 로그아웃하면 조회 데이터를 비웁니다.

비밀번호 원문·해시·세션 토큰은 목록 API에 포함하지 않습니다. **재설정**은 관리자 비밀번호 확인 후 학생에게 새 비밀번호를 지정합니다. 기존 가입 비밀번호 정책(8자 이상, UTF-8 72바이트 이하, 취약한 비밀번호 제외)을 적용하며 관리자당 5분간 최대 10회 시도할 수 있습니다. 변경 성공 시 학생의 로그인 세션을 폐기하고, 승인 상태·프로필·개인 필기는 유지합니다. 관리자 계정의 비밀번호는 이 기능으로 변경할 수 없습니다. 비밀번호를 브라우저 저장소나 로그에 저장하지 않고, 요청 시 입력란을 비웁니다.

`migrations/20261119-admin-members.sql`은 인증 강화·생일·출석번호 마이그레이션 이후에 적용합니다. 기존 로그인/가입 함수를 교체하지 않습니다. `tests/admin-members.cjs`와 `tests/admin-members.sql`에서 권한, 정보 최소 반환, 재확인·정책·요청 제한, 세션 폐기와 오래된 응답 무시를 확인합니다.

## 개인 공부방

**폴더**에서 새 폴더 생성·이름 변경·삭제를 할 수 있으며, 왼쪽 메모를 폴더나 미분류로 드래그하여 이동합니다. 메모 제목 아래의 폴더 선택으로도 이동할 수 있습니다. 새 메모는 먼저 저장한 뒤 분류합니다. 전체 필기·미분류·개별 폴더 필터와 제목 검색을 함께 사용하며, 기존 제목 날짜 정렬은 유지합니다. 폴더 삭제는 메모를 삭제하지 않고 미분류로 이동시킵니다.

`migrations/20261119-study-folders.sql`은 공부방 기본 마이그레이션 이후, 폴더 UI 배포 전에 적용합니다. 폴더와 분류 정보는 각 회원 본인에게만 보이는 서버 데이터이며 다른 기기에서도 동일합니다. 본문·저장 버전과 별도 관리하므로 폴더 이동이 미저장 글을 덮어쓰지 않습니다. 폴더 목록은 공부방 진입·새로고침 때 조회하며 타이핑 중에는 서버에 요청하지 않습니다. `tests/study-folders.cjs`와 `tests/study-folders.sql`은 기본 검사에 포함됩니다.

아이콘 도구막대에서 문단 스타일, 글자 크기, 굵게·기울임·밑줄·취소선, 글자색·형광펜, 정렬, 글머리 기호·번호 목록, 목록 들여쓰기·내어쓰기를 설정합니다. 버튼에 마우스를 올리면 기능 이름과 단축키가 표시됩니다. **서식 지우기**는 선택한 글자의 서식과 문단 정렬을 초기화하며 제목·목록·표 구조는 유지합니다.

**글자 크기** 메뉴에서 기본 크기 또는 10·11·12·14·16·18·20·24·28·32·36·48px를 선택하거나 −/+ 버튼으로 조절합니다. 선택 영역이 있으면 해당 글자에, 없으면 이후 입력에 적용합니다. 코드 블록은 고정 크기를 유지합니다. 일반 Markdown에 없는 크기·색상·밑줄·취소선·정렬을 지정한 문단·목록·표는 `codewiki-rich-v1` 데이터 블록으로 보존합니다. 이 사이트에서 다시 가져오면 서식이 복원되지만, 외부 Markdown 뷰어에서는 해당 블록이 데이터로 표시됩니다.

승인된 학생 로그인 후 **내 공부방** 또는 `#study`에서 개인 필기를 작성합니다. 글을 선택하고 굵게·형광펜·기울임·제목·목록·인용·코드를 누르면 본문에 바로 적용됩니다. 선택 없이 굵게·형광펜을 켜고 이어서 작성할 수도 있습니다. Ctrl+B는 굵게, Ctrl+I는 기울임, Ctrl+Alt+K는 코드 블록 전환, Ctrl+Z는 실행 취소, Ctrl+Shift+Z는 다시 실행, Ctrl+S는 저장입니다. macOS에서는 Ctrl 대신 Command를 사용합니다. 노트를 바꾸면 실행 취소 기록도 분리됩니다. 기존 Markdown 노트는 서식이 적용된 모습으로 열리며 UTF-8 TXT/MD 가져오기와 MD 내려받기를 지원합니다. 제목은 120자, 저장되는 Markdown 본문은 20만 자까지 지원합니다.

**표 삽입**은 머리글을 포함한 3행 3열 표를 만듭니다. 표 안에 커서를 두면 행·열 추가/삭제와 표 삭제 버튼이 나타나고, Tab/Shift+Tab으로 셀을 이동합니다. 일반 표는 Markdown 표로 저장합니다. 여러 문단·목록·병합 셀 등 일반 Markdown 표로 표현할 수 없는 내용은 `codewiki-table-v1` 데이터 블록으로 보존하며, 이 사이트에서 다시 가져오면 표로 복원합니다. 외부 Markdown 뷰어에서는 해당 복합 표가 데이터 블록으로 보일 수 있습니다. 표 기능은 [Tiptap Table](https://tiptap.dev/docs/editor/extensions/nodes/table)을 사용합니다.

본문 도구막대와 표 편집 메뉴는 스크롤 중에도 검색창 아래에 고정됩니다. 단축키는 본문에 커서가 있을 때 적용되며, 도구 버튼에 마우스를 올리면 툴팁으로 확인할 수 있습니다. 행 추가·삭제 메뉴에서 위쪽 또는 아래쪽, 열 추가·삭제 메뉴에서 왼쪽 또는 오른쪽을 선택합니다. 현재 셀과 커서는 유지되며, 삭제는 선택한 방향에 바로 붙어 있는 이웃 행·열에 적용됩니다. 해당 방향에 이웃이 없으면 삭제 항목이 비활성화됩니다. 여러 셀을 선택한 경우 선택 범위의 바깥 경계를 기준으로 합니다. macOS의 Ctrl은 Command, Alt는 Option입니다.

**저장** 버튼 또는 Ctrl+S로 서버에 저장합니다. **저장됨** 표시를 확인하면 다른 기기에서도 같은 학생 계정으로 목록을 열 수 있습니다. 전송되지 않은 현재 필기는 계정별 브라우저 임시 저장소에 보관하고 다시 로그인/접속할 때 복원합니다. 브라우저 저장이 차단되거나 가득 찼다면 안내가 나오므로 서버 저장 또는 내려받기를 사용하세요. 다른 창/기기에서 바뀐 노트는 자동 덮어쓰지 않습니다. 현재 글을 내려받아 보관하고 **서버 글 불러오기**로 최신본을 확인한 뒤 내용을 합칠 수 있습니다. 삭제는 확인 후 영구 삭제됩니다.

`migrations/20261118-study-notes.sql`은 기본 DB 구성 이후 적용합니다. 2026-11-18 기존 Supabase에 적용하고 `tests/study-notes.sql`의 롤백 검사를 통과했습니다. `cw_study_notes`는 RLS를 켜고 직접 테이블 접근을 차단하며 학생 공부방을 활성화하려면 `migrations/20261119-student-study.sql`을 적용하고, 관리자 공부방 폐기는 필기 이전 후 `migrations/20261119-student-only-study.sql`을 적용합니다. RPC는 학생 승인 상태·세션 만료·소유 계정·수정 버전을 검사하며, 관리자 계정은 공부방 기능 자체를 사용할 수 없으며, 학생은 본인 개인 노트에만 접근할 수 있습니다. 승인 대기·반려·만료된 세션은 차단합니다. 이 추가 마이그레이션은 기존 노트나 인증 함수를 변경하지 않으며, 기본 공부방 SQL을 나중에 다시 실행하면 학생 접근이 막히므로 추가 마이그레이션을 다시 적용해야 합니다. HTML·외부 이미지 삽입을 지원하지 않습니다. Markdown을 제한된 문서 구조로 변환하며 HTML은 실행되지 않는 글자로 취급합니다. 노트 본문은 GitHub에 저장하지 않습니다.

## 코드 구조와 유지보수

문서 데이터는 index.html의 스크립트 순서대로 조합한 뒤 app.js가 읽습니다. 실행 중 문서를 변경하는 구조는 아니므로 검색용 소문자 텍스트와 역링크 색인은 한 번 만들고 재사용합니다. 문서 데이터를 동적으로 바꾸는 기능을 추가한다면 색인 무효화도 함께 구현해야 합니다.

인증은 auth.js가 담당하고 프로필·학습 기록·생일·관리자 화면에 세션을 전달합니다. admin.js는 승인 목록을 표시하는 역할만 맡으며, 반 필터는 이미 읽은 목록에 적용합니다. 게시판은 같은 세션에서 동시에 시작한 조회만 공유하고, 쓰기 성공 후에는 새로 조회합니다. 화면 이동·팝업 닫기·세션 변경 이후 도착한 응답은 해당 화면을 갱신하지 않습니다.
